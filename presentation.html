为什么只给 Agent 一个“小钱包”还不够？

小额钱包只能限制最大损失，不能限制钱最终流向哪里。

仅余额限制的钱包 (Balance-Only Wallet)
钱包余额: 0.02 AVAX
恶意请求: 0.001 AVAX
✓ 金额小于钱包余额
这笔支付仍可能被允许 ✕
小钱包只能限制“最多损失多少”，无法限制“钱可以付给谁”。
AVAFENCE 资金权限层
请求金额: 0.001 AVAX [✓ 金额合法]
收款方: 未知黑客地址 [✕ 不在白名单]
执行机制: 智能合约策略强制执行
未授权价值转移被阻止 🛡️ (BLOCKED)
交易被 Fuji 接受，但 AvaFence 阻止未授权价值转移。
小额支付 ≠ 安全支付
模型可能被骗，规则仍然有效。 (The model can be tricked. The rules still hold.)

为什么选择 Avalanche？

自主 AI Agent 的机器工作流，需要快速、低成本、可验证的机器支付基础设施。

01 · Fast Finality
快速确认
快速终局确认。Agent 完成支付后，需要快速继续下一步任务。
02 · Low-Cost Transactions
低成本交易
低成本交易。适合 Agent 频繁发生的数据、API、算力和推理服务小额支付。
03 · Verifiable Execution
链上可验证
链上可验证。人类、Agent 与商户可以验证：Policy 状态、支付结果与拦截记录。
AvaFence 利用 Avalanche 快速、低成本、可验证的执行能力，构建 Agent 机器支付闭环。
