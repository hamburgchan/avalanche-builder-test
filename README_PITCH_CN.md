### Page 1 — 困境引入 (0:00–0:20)
- **屏幕主标题**：如果 AI Agent 可以自己花钱，你敢把钱包交给它吗？
- **屏幕副标题**：AI Agent 已经可以思考、调用工具和 API。当它开始拥有支付能力，新的问题出现了。
- **两张卡片**：
  - 左卡：`人工逐笔审批` ➔ `安全，但不自主`
  - 右卡：`直接开放钱包权限` ➔ `自主，但不安全`
- **底部结论**：我们缺少一层新的资金权限控制。(There is a missing layer.)
- **讲者中文话术**：
  > “各位评委老师好！AI Agent 已经越来越聪明，能做深度推理，能调用各种 API。但如果下一步它开始拥有自主花钱的能力——你敢直接把钱包私钥交给它吗？每一笔都让人类手动点批准，它就不再自主；直接把钱包权限彻底交给它，提示词注入或者越权消费会把资金洗劫一空。这中间缺少了一层新的资金权限控制。”

### Page 2 — 真实刚需 (0:20–0:45)

### Page 3 — 核心创新 (0:45–1:05)
- **屏幕主标题**：缺的不是另一个钱包
- **屏幕副标题**：而是一层资金权限控制 (Financial Permission Layer)
- **大字对比卡**：
  - 钱包控制：**谁可以动钱**
  - AvaFence 控制：**这笔钱在什么条件下可以被花出去**
- **架构流**：AI Agent ➔ 支出意图 (Spend Intent) ➔ AVAFENCE 链上权限引擎 ➔ 支付通道 ➔ 服务商
- **权限维度**：给谁 · 花多少 · 什么时候 · 一天能花多少 · 哪个请求
- **讲者中文话术**：
  > “大家都在做钱包，但缺的根本不是另一个钱包！AvaFence 是一层独立的资金权限控制层（Financial Permission Layer）。普通钱包只管‘谁可以动钱’，而 AvaFence 管的是‘这笔钱在什么条件下可以被花出去’。我们在 Avalanche 智能合约上硬编码了单笔硬顶、每日预算、商户白名单和防重放 Nonce。我们给 Agent 自主权，但把资金限制在明确的链上边界内！”

### Page 4 — 击碎小额钱包质疑 (1:05–1:20)
- **屏幕主标题**：为什么只给 Agent 一个“小钱包”还不够？
- **屏幕副标题**：小额钱包只能限制最大损失，不能限制钱最终流向哪里。
- **对比卡**：
  - 左（普通小额钱包）：余额 0.02 AVAX，恶意请求 0.001 AVAX，因低于余额仍可能被允许放行！
  - 右（AvaFence 权限层）：金额 0.001 AVAX 合法，但收款方为**未授权收款地址**，**未授权价值转移被阻止 🛡️ (BLOCKED)！**
- **底层链上准确语义**：
  - **交易被 Fuji 接受，但 AvaFence 阻止未授权价值转移。**（切勿表述为“Avalanche 拒绝了交易”，Avalanche 正常打包了交易，是由 AvaFence 智能合约在执行期阻止了转账）。
- **底部大字**：小额支付 ≠ 安全支付。模型可能被骗，规则仍然有效。(The model can be tricked. The rules still hold.)
- **讲者中文话术**：
  > “很多人会说：给 Agent 专门开一个小额钱包不就安全了吗？根本不够！小额钱包只能限制最多损失多少钱，根本无法限制钱最终付给谁。一旦 Agent 遭遇提示词注入，被诱骗转走 0.001 AVAX，小额钱包依然会付款。而在 AvaFence 里，即使金额再小，只要是未授权收款地址，智能合约直接阻止价值转移！小额支付不等于安全支付。模型会被忽悠，但链上规则仍然有效！”

## 九、评委常见 Q&A 杀手锏应答

### Q1: “这和多签钱包（Gnosis Safe）有什么区别？”
> **应答**：“多签钱包解决的是‘多个人如何共同审批’，依然依赖人类持续签名；而 AvaFence 解决的是‘**人类不介入的情况下，AI Agent 如何在安全围栏内自主花钱**’。人类只需提前设定一次规则，Agent 就能在规则内自主运行。”

### Q2: “为什么不直接用账户抽象（ERC-4337）的 Session Key？”
> **应答**：“Session Key 只能粗粒度限制合约函数与金额上限；而 AvaFence 是一个**专门针对 AI Agent 行为特征设计的应用级权限策略引擎**，支持单笔硬顶、滚动日预算、商户严格白名单、非对称防重放 Nonce 与商户端闭环核验。未来我们可以无缝封装为 ERC-4337 验证器插件。”

### Q3: “商户如何确认 Agent 真的付款了？”
> **应答**：“商户提供轻量级验证服务，通过监听 Avalanche Fuji 的 `PaymentExecuted` 事件，严格核对交易哈希、RequestId、Agent 地址与付款金额。只有全部吻合，商户才释放付费 API 或数据资产。”
